# Cilium 1.20 and Spegel 0.8

!!! abstract "Summary"

    **2026-10-16.** Cilium went from 1.18.6 to 1.20.2 in three steps, and
    Spegel to 0.8.0. Each step was verified before the next. No outage.

## Why

Spegel 0.8.0 dropped its `hostPort` mirror and relies on the Service's
`trafficDistribution: PreferSameNode` to send image pulls to the Spegel pod
on the same node. Cilium only honours that from 1.20 on. Separately, the
charts mirror the cluster used had stopped publishing Cilium after 1.18.6, so
Renovate had gone quiet without any sign.

## Steps

1. Spegel 0.8.0 ([#2883](https://github.com/bykaj/home-ops/pull/2883)).
2. Cilium 1.18.15 ([#2885](https://github.com/bykaj/home-ops/pull/2885)),
   with the chart moved to `oci://quay.io/cilium/charts/cilium`.
3. Cilium 1.19.9 ([#2886](https://github.com/bykaj/home-ops/pull/2886)).
4. Cilium 1.20.2 with `loadBalancer.serviceTopology: true`
   ([#2887](https://github.com/bykaj/home-ops/pull/2887)).

## What went wrong

The Spegel Service still carried `service.kubernetes.io/topology-mode: auto`
from the bootstrap install, which overrides `trafficDistribution`, so pulls
weren't node-local until it was removed by hand. See
[KB-005](../troubleshooting/kb/005-bootstrap-helm-field-manager-leftovers.md).

## What to watch

Check that pulls stay node-local after a Cilium or Spegel upgrade. In the
`cilium-agent` on each node:

```sh
cilium-dbg bpf lb list | grep :30020   # one local backend per node
```

The `spegel-registry` EndpointSlices should also carry `hints.forNodes`.
When a chart source stops publishing, Renovate says nothing, so check the
chart source if a core component gets no updates for a while.
